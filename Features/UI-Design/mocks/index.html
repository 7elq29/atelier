For your question — I've read the full doc. Here's the goal and suggested steps:

Goal

Integrate logging failover mitigations with Outage Mitigator (OMG) so an on-call engineer can apply them in one command during an incident. Three levers:

LeverPhaseHow fastStatus
Namespace samplingPhase 1~60s (Flip)Ready to implement
Throughput quotaPhase 2~30 min (or seconds with breakglass)Ready to implement
RetentionPhase 3BlockedBlocked on Pinot team

Root cause from incident #117865: throughput quota is compute-based (baseline × CPU count). After failover, services absorb double traffic without scaling CPU — quota doesn't move and the cluster drowns while dashboards still show everyone under quota.

Suggested Steps (13 tasks)

Phase 1 — Sampling (no external dependencies)

  • Task 1: Build the sampling OMG plan + plugin (logging/sample_namespaces)
  • Task 2: Make the plan snapshot prior state so revert script can restore
  • Task 3: Start Charter policy (long lead time — begin immediately)
  • Task 4: Write revert script (sampling only first; structured to add throughput/retention later)

Phase 2 — Throughput quota

  • Task 5: Ship region-aware Flip block map (compute_based_throughput_quota_blocked_namespace)
  • Task 6: Build throughput cut OMG plan (calls ThroughputQuotaUpdate, persists prior values)
  • Task 7: Chain breakglass deploy node (otherwise cut takes 30 min–hours to propagate)
  • Task 8: Extend revert script to throughput (unblock after restore — ordering is critical)
